Your coding agent is the ghost in your machine.

It installs packages, runs setup scripts and follows READMEs on your computer, with your permissions. Spook watches what it is about to run, stops only the dangerous part, and tells you why. It runs locally, with an open model, so nothing leaves your machine.

What it looked like

A fresh Claude Code session was asked to "set up this project and get it running" in a deliberately haunted demo app. The agent tried to install the dependencies:

$ sed -i '/spook-demo-marigold-candles/d' package.json && npm install --ignore-scripts 2>&1 | tail -5
Spook blocked npm:spook-demo-marigold-candles (does not exist on npm:
hallucinated or squatted name); local:vendor\papel-picado (runs an install
script, ./install.js: collects all environment variables
(`JSON.stringify(process.env`), contacts a raw IP (`https://203.0.113.7`),
collects secrets and has network access). Nothing was run.

A few seconds later, a local Gemma model explained a different block, an attempt to send an SSH key, to the developer in plain English:

The agent attempted to send the contents of your private SSH key to an external server. This is risky because it could expose your credentials. Please review your command and remove the cat ~/.ssh/id_rsa portion before running it again.

Both are real output; Spook's reply is slightly shortened. The demo's traps are inert and point at a reserved address that goes nowhere.

What it stops

Packages that do not exist
Names an AI hallucinated, which attackers register and fill with malware.
Look-alike names
A package one letter away from a popular one, especially when it is brand new.
Malicious install scripts
Spook reads postinstall and setup.py code straight from the archive, without running it, and looks for credential theft, obfuscation and raw-IP traffic.
Instructions hidden for AI
When a README or web page tells AI agents what to do, Spook warns the agent and blocks the packages and links that came only from that page.
Irregular behaviour
Encoded commands, download-and-run in one step, reading SSH keys next to a network call, deleting outside the project.
Tampering with Spook
The agent can read Spook's memory but cannot change it or approve its own blocked packages.

How it decides

  1. It remembers what you asked for. Your own words count as trusted.
  2. It notes what the agent reads. Packages and links from READMEs, web pages and command output are marked as coming from there.
  3. Rules decide, before every command. Registry checks, archive inspection and behaviour rules score each item. Only the risky item is blocked, and the agent is told why. This takes well under a second.
  4. Gemma explains, afterwards. A local gemma3:4b writes a short explanation for you and shows it as a notification. The model never makes the decision.
  5. The Book of the Dead remembers. Packages that are bad in themselves are blocked instantly next time. You approve or forget entries from your own terminal.

Try it

Spook is one Python file with no dependencies. It plugs into Claude Code as a hook.

git clone https://github.com/mohitbaher/spook
python spook/hook.py install path/to/your/project
ollama pull gemma3:4b       # optional, for the explanations

Then start a new Claude Code session in that project. See what Spook remembers with python spook/hook.py book, and approve something it blocked with python spook/hook.py allow npm:name.

Why local and open

A security tool that uploads your unreleased code and your agent's commands to someone else's server is a strange kind of guard. Spook's rules are a file you can read and change. The explanations come from an open-weight model on your own GPU, so they cost nothing and keep working offline. If a smaller or better model comes along, you swap one setting.

What it is not

Spook is a tripwire, not a sandbox. It catches the common attacks and explains them; a determined attacker can phrase things to slip past rules. For real isolation, run agents in a container. Spook is the layer that still speaks up when the agent itself does not.
